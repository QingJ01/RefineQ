# RefineQ 统一侧栏与跨空间总日历设计

## 背景

RefineQ 已经在学习首页、单个学习空间和管理后台使用左侧栏，但每个页面独立维护导航结构；账户页仍然采用独立页头与卡片网格。结果是同一个产品在不同路由中出现不同的信息层级，用户离开学习空间后也无法从全局层面看到所有空间的学习安排。

本次设计解决两个根问题：其一，所有登录后页面共享稳定的全局导航；其二，学习任务虽然由各学习空间拥有，但用户需要一个只读的跨空间时间视图。

## 第一性原理

1. **任务归属于学习空间，日历视图归属于用户。** 总日历不能复制或重新拥有任务，只能投影用户有权访问的空间任务。
2. **全局视图负责发现和分流，空间视图负责修改和执行。** 总日历汇总查看，点击任务进入对应空间；改期、完成和练习仍在空间上下文内完成。
3. **导航只能有一个事实来源。** 登录后页面复用同一个侧栏组件，通过上下文插槽展示空间、账户或管理功能，避免复制结构与样式。
4. **聚合必须发生在服务端且有范围上限。** 前端不能并发下载每个空间的完整快照。服务端只返回指定日期范围内的轻量任务投影，并强制 owner 隔离。

## 信息架构

统一侧栏分为四层：

- 品牌区：RefineQ 标识。
- 全局导航：学习首页、跨空间总日历。
- 学习空间区：进入全部空间的入口、最近活跃空间列表；处于某个空间时，追加今日学习、学习路径、资料库、空间日历和学习进度。
- 工具区：账户设置、管理员入口（仅管理员）、语言和退出。

账户页在侧栏上下文区显示个人资料、密码安全、数据与会话、危险区域的页内锚点。管理后台在同一区域显示系统概览、运行维护和集成配置。视觉结构、宽度、底部工具区和移动端行为保持一致。

## 跨空间总日历

新增前端路由 `/calendar`。月视图按学习空间分配稳定颜色，日期单元显示任务摘要；右侧议程列出选中日期的全部任务，并提供空间筛选。页头展示当月任务数、总学习时长和涉及空间数。

任务卡片包含空间名称、主题名称、活动类型、计划时间、时长和状态。点击“进入空间任务”跳转到 `/learn/{workspaceId}/calendar?session={sessionId}`，空间日历自动切换到任务所在月份、日期并突出对应任务。归档空间默认排除，可由用户显式纳入。

总日历不提供改期、完成或删除操作。空状态区分“该月没有任务”和“尚未创建学习空间”；请求失败时保留当前月份并提供重试。

## 后端边界

新增用户级 `GET /calendar`：

- 查询参数：`starts_at`、`ends_at`、`include_archived=false`。
- 时间范围采用 `[starts_at, ends_at)`，必须为带时区时间，且跨度不超过 370 天。
- 响应只包含轻量任务投影：空间 ID/名称/归档状态、任务 ID、主题 ID/名称、活动、时间、时长和状态。
- 服务端先按 owner 列出空间，再读取其学习计划；没有计划的空间直接跳过。
- 返回结果按计划时间、空间名称和任务 ID 稳定排序。

该接口不接受 owner 或 workspace 列表参数，权限边界只由认证身份决定。

## 前端组件

- `AppSidebar`：纯展示组件，接收 locale、空间列表、当前路由、用户角色、上下文导航和操作回调。
- `GlobalCalendarRoute`：恢复会话，加载用户、空间和月度任务，处理未认证与重试。
- `GlobalCalendar`：月历、空间筛选、统计与日议程；不直接写后端。
- `ScheduleCalendar`：新增可选的 focused session，支持深链接定位并突出任务。

保持现有 Manrope、暖灰纸张背景、蓝色动作色和编辑式排版。侧栏增加空间色点、最近活跃时间与分组层级，提升信息密度，但不添加无数据支持的进度或虚构提醒。

- 前端测试覆盖 API 契约、月度分组、空间筛选、共享侧栏结构、账户锚点和深链接定位。
- 完整运行 Python 测试、前端测试、ESLint、Next.js 构建和浏览器视觉验证。
