# RefineQ 交互完成度优化设计

## 背景与目标

现有版本已经具备认证、学习空间、计划、资料、练习、证据、Agent 和管理后台主流程，但部分交互仍停留在“接口存在、页面能点”的层面。本轮不改技术栈、不重做布局，重点完成考试型学习者每天会反复使用的操作闭环，并消除浏览器原生弹窗、内部引用编号、全局互锁和缺失页面状态带来的产品感断层。

验收目标：学习者能从计划或薄弱知识点直接开始指定主题练习，选择难度，跳过不合适题目，收藏题目并再次练习；题目和判分引用可以查看真实资料片段；资料、对话和学习空间的危险操作都有一致、可访问的确认流程；加载、空白、失败、404 与未保存状态都提供明确下一步。

## 方案选择

本轮采用“针对现有闭环做完成度升级”：保留 FastAPI、现有持久化仓库、Next.js App Router、React 和当前 RefineQ 视觉语言。相比全面视觉重写，该方案风险更低且直接增加可用功能；相比继续引入大型学习模块，该方案先兑现当前界面已经暗示的能力，避免功能面继续扩张却留下更多半成品。

## 练习闭环

练习接口增加可选主题、难度和替换当前题目的参数。学习记录维护单调递增的题目序号，确保跳题不会重复使用题目 ID。每道生成题保留经过所有权隔离的内部历史，收藏只保存题目 ID 与时间，公开响应永远排除参考答案和评分规则。

题目响应与判分响应同时返回经过校验的资料片段，而不是只返回 citation ID。前端使用同一个来源抽屉展示文件名、片段和匹配度。学习者可以使用“自适应”或 1–5 级难度，主动换题、收藏/取消收藏、生成同主题同难度的新题。收藏题目在练习卡内可查看、再次练习和取消收藏。

计划节点和掌握度建议增加“开始练习”动作，统一调用主题定向出题，不引入新的页面或项目概念。计划完成/顺延操作使用行级忙碌状态，避免重复提交；练习请求不再锁住学习首页或其他无关操作。

## 一致的操作反馈

新增通用确认对话框，处理学习空间删除、资料删除、会话删除和后台未保存跳转。对话框具备语义化标题、说明、取消/确认按钮、Escape 关闭、焦点进入与返回。学习空间重命名改为卡片内编辑，支持 Enter 保存、Escape 取消，不再调用 `window.prompt`。

资料区补齐搜索无结果、清空搜索、文件详情、删除中状态和上传队列清理；搜索结果可以直接打开来源抽屉。Agent 增加建议问题、自动滚动、复制失败反馈、本地化模型状态，以及管理员进入模型设置的入口。

后台保留浏览器关闭时的标准 `beforeunload` 保护，但应用内跳转改用自定义确认对话框。加载失败期间不渲染可编辑的默认配置；首次加载使用与页面结构一致的骨架屏。

## 页面状态、可访问性与视觉

新增全局 loading、error 和 not-found 页面。Source Drawer 补齐本地化、焦点循环、关闭后焦点恢复和无来源空态。按钮使用行级或区域级 busy 状态与 `aria-busy`；状态消息通过 live region 播报。移动端确认框、来源抽屉、练习工具栏和资料操作保持至少 40px 触控面积。

视觉继续使用冷灰画布、钴蓝主操作与暖杏辅助色。新增界面不堆叠同质卡片，而使用工具条、内联编辑、分段控制和轻量抽屉维持现有层级。所有新文案提供中英文键值，移除面向用户的内部状态词和未本地化英文。

## 错误处理与验证

后端对未知主题、过期题目、越权收藏和非法难度返回稳定错误；替换题目不改变掌握度，也不生成虚假作答证据。前端在请求失败时保留当前题目、答案和收藏列表，允许重试。

测试采用 TDD：Python 单元/集成测试覆盖定向难度、换题唯一 ID、来源公开过滤、收藏持久化和所有权；Vitest 覆盖新组件语义和 API 参数；Playwright 覆盖计划定向练习、难度、跳题、收藏、来源抽屉、自定义确认以及后台未保存跳转。最后执行全部 Python 测试、Ruff、Vitest、ESLint、Next build 和 Playwright，并进行敏感信息与工作区审计。
