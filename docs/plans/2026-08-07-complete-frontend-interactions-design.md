# RefineQ 完整前端交互闭环设计

## 目标与原则

本次改造把当前“接口可调用、页面可展示”的学习 MVP 补成可以连续使用的个人学习 Agent。范围覆盖自动学习空间、今日计划、AI 出题判分、资料、学习证据、Agent 对话、认证、管理后台、路由、国际化和无障碍。视觉继续沿用现有 RefineQ：冷灰画布、钴蓝主操作、杏色辅助、克制圆角与轻阴影，不引入新的视觉体系。

交互遵循四条原则：系统自动判断时必须可解释、可撤销；异步操作必须立即反馈、可取消、可恢复；后端已经返回的学习依据不能在前端丢失；所有重要状态都能通过刷新、浏览器历史或重新登录恢复。学习空间继续保持“隐式”概念，用户不需要管理项目，但可以纠正、归档和删除错误空间。

## 信息架构与状态

根页面继续承担认证和学习首页。进入空间后，使用 `/learn/[workspaceId]/[section]` 表达 `today`、`materials`、`evidence`、`coach` 四个分区；旧的本地 `section` 状态只负责过渡，不再是唯一事实来源。浏览器前进、后退、刷新和复制链接都恢复相同空间与分区。用户主动返回学习首页时清除当前选择，而不是在刷新后强制跳回旧空间。

学习首页显示真实可操作的“开始学习”和“最近学习”锚点。自然语言路由完成后展示短暂但可操作的判断条：动作、目标空间、原因、置信度，以及“撤销/改选最近空间”。低置信度结果不静默切换。空间卡提供归档和删除，但保持轻量，不改成项目管理器。

语言偏好单独持久化，并同步 `<html lang>`。请求状态从一个全局 `busy` 拆成路由、练习、上传等独立状态，避免无关区域互相锁死。

## 学习、资料与 Agent

今日页把计划从静态时间线变为任务列表：开始、完成、延期和恢复；完成状态写入后端并反映到进度。进度区域增加主题掌握度、最低掌握主题和推荐下一步。练习卡完整显示题目难度、生成模式、引用资料；评分后显示评分模式、引用、参考讲解、正确点、缺口和误区，并提供跳过、收藏、重练和下一题。

资料区实现点击与拖拽上传、客户端格式和大小检查、逐文件队列、进度/状态、取消与失败重试。资料可以查看元信息、搜索片段、下载原文件和删除。上传与解析错误停留在对应文件行，不再只依赖页面顶部错误条。

Agent 采用乐观消息：发送后用户消息立即出现，回答显示生成状态；支持停止、重试、复制和新对话。会话列表与消息由后端提供，切换分区、刷新或重新登录后可恢复。引用不再显示内部 ID，而是可展开的来源抽屉，包含文件名、片段和相关度。对模型未配置、超时和网络失败分别提供可恢复动作。

## 管理、认证与可访问性

管理后台维护明确的初始值、草稿值和 dirty 状态。存在未保存修改时，侧栏跳转、返回学习页和刷新都会提示；测试连接只允许测试已保存版本，或通过“保存并测试”一次完成，杜绝测试旧配置。保存成功提示不会因组件重挂载消失。加载失败时表单只读，避免默认值覆盖真实配置。

认证补充密码可见切换、密码规则、字段级错误、自动填充属性和密码找回流程。密码找回在开发/黑客松环境返回一次性重置令牌供页面继续完成，在生产环境只返回统一成功提示，避免泄露账号存在性。

所有图标按钮有可访问名称；活动导航使用 `aria-current`；选项卡使用正确语义；聊天、上传和保存结果通过 live region 播报；错误出现后聚焦到错误摘要；键盘焦点清晰；移动端触控目标不小于 40px；尊重减少动画偏好。

## 错误处理与验收

后端所有新资源仍从认证用户和 `workspace_id` 派生，不能由客户端指定 owner。删除空间和资料使用确认流程，并在后端保持 owner 隔离。Agent、资料、计划和密码重置接口使用稳定错误码。前端对超时、配额、解析失败、模型未配置和会话冲突分别给出下一步操作。

验收以测试和真实浏览器共同证明：Python 单元与集成测试覆盖新接口及隔离；Vitest 覆盖状态投影和组件语义；Playwright 覆盖注册、自动路由纠错、URL 恢复、计划完成、资料拖拽/搜索/删除、练习引用、Agent 会话恢复、密码重置、管理配置保护以及 390px 移动端键盘/可访问名称。最终运行完整 Python 测试、前端测试、Lint、Build 和 Playwright，并保存当前运行截图。
