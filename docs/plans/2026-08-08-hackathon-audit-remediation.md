> 审查日期：2026-08-08
>
> 实施基线：origin/main@64515b1
>
> 范围：仓库内代码、配置、自动化测试和技术文档；访谈、部署执行和参赛材料不在本轮范围。

## 1. 第一性原理

本轮不以“把清单逐项改掉”为目标，而以这些不可妥协的不变量为判断标准：

1. 掌握度只能由独立、可归因且足够充分的学习证据改变；同一道题的重做不是新证据。
2. 模型输出是不可信建议，不是掌握度事实；确定性门槛必须在模型之外成立。
3. 数据库事务只包围一致性读写，不能跨越模型、Embedding、OCR 等外部网络调用。
4. 客户端身份只能由明确的可信代理提供；默认配置必须安全且可验证。
5. 计划、反馈和资料如果被保存，就必须被下游消费；否则不应宣称形成闭环。
6. 系统不能制造误区、主题或引用；需要推断时必须展示为建议并由用户确认。
7. 生产功能写入的数据必须位于持久卷，且备份源与备份目标必须物理分离。
8. 可观测性不能泄露答案、材料、令牌或稳定用户标识。

## 4. 被驳回的原方案

### B-02 不修改为“两个 streak 互不清零”

难度策略的业务规则是“连续两次独立同向证据才升降”。现实现会在相反结果出现时清空另一方向状态，符合该规则。原方案若保留两个计数器，会让“对、错、对”在第三次错误升级，直接违反连续语义。

处理：不改生产算法，只补参数化回归测试，覆盖连对、连错、交替、重做同题和边界等级。

### B-05 不改标准 BKT 转移方程

答错后的非零下界来自“每次学习机会之后仍可能发生学习”的标准 BKT 转移，不是数值错误。直接只在答对时应用 p_learn 会改变模型含义及全部历史数据。

处理：保留方程；把 evidence_count 与 mastery_is_stable 接到 API 和界面，只有概率、证据数量和定性门槛同时满足时才显示“已掌握”。

### D-01 不在降级判分中制造 misconception

回答缺失、偏题或证据不足只能形成 gap，不能凭空断言学习者存在某个误区。处理：渲染真实 misconceptions；空数组时不显示该栏。

### E-03 不自动把上传内容写成主题

材料是不可信数据，自动改写主题会破坏掌握度连续性。处理：只从标题和显式标签生成有界候选，展示为建议，用户确认后再原子地追加主题。

## 5. 仍需落地的真实缺陷

### P1：掌握度与安全

- 同一道 question_id 可通过重做路径多次更新 BKT；重复答错也可重复降低难度。
- AI 判分主路径无条件把 mastery_evidence 设为真。
- 密码重置接口没有使用认证限流桶。
- Compose 信任任意 X-Forwarded-For，公网撞库可绕过 IP 限流。
- 模型调用位于问题、空间路由和教练会话的数据库事务内。
- PostgreSQL 嵌套 owner_transaction 静默跳过内层 advisory lock。

### P2：产品闭环与生产可用性

- 前后端最弱主题平局规则不一致。
- 公网裸 /health 路由缺失，容器健康探测启动过慢。
- 管理备份写到只读根文件系统，且没有独立持久卷。
- 判分卡不显示真实误区，AI/降级模式文案没有渲染。
- 教练上下文使用内部 topic ID；降级和意图容量拒绝缺少安全日志。
- 非 review 计划活动不影响学习模式，作答后也不会完成对应计划会话。
- 历史 gaps 和 misconceptions 不进入下一题生成上下文。
- 前端没有初始诊断入口。
- 分块没有上下文重叠；混合检索直接混合不同尺度的分数且缺少语义阈值。
- 未被生产调用的自适应诊断、错误解析、推荐和文件模型配置实现增加了虚假能力表面积。

## 6. 解决方案与可证伪验收

| 领域 | 最小正确方案 | 失败时必须暴露的测试 |
| --- | --- | --- |
| 独立证据 | 每个主题保存最近已计入的 question_id；首次有效证据后，同题任何重做均不再改变 BKT 或难度 | 同题错→错、错→对、对→错只更新一次；不同题正常累计 |
| AI 判分 | 本地实质性门槛 AND 模型 sufficient_evidence；二者任一为假都不更新掌握度 | 空白式、复读、偏题和模型误报不更新；充分答案更新 |
| 稳定掌握 | API 返回每主题 stable；界面只对 stable=true 显示“已掌握” | 高概率但证据少仍显示“进行中” |
| 代理安全 | Compose 使用确定的代理地址，API 只信任该地址；禁止默认星号 | 直连伪造头不能换 key；可信代理能区分终端客户端 |
| 备份 | REFINEQ_BACKUP_ROOT 指向独立 /backups 持久卷 | 只读根文件系统拓扑下创建、重建后列出、校验均成功 |
| 计划闭环 | plan_session_id 决定 topic 与 mode；有效作答完成该 session | learn/practice/apply/review 分别映射 concept/case/project/exam |
| 反馈闭环 | 最近同主题的 gaps/misconceptions 作为有界不可信上下文交给下一题 | 其他主题不泄漏；最多取最近三次；提示词明确不可信 |
| 事务 | 外部调用前后分别使用短事务，提交时重新检查幂等键和版本 | 阻塞 transport 时可从第二连接读取；并发相同 request/turn 只落一份 |
| 检索 | 句段优先分块并保留约 12% overlap；使用带阈值的加权 RRF | 跨边界事实可检索；低相似度向量不返回；排名对尺度不敏感 |
| 可见性 | 只渲染真实字段；日志只含事件、原因、耗时和模式 | 日志中不出现答案、材料正文、token、邮箱或 owner_id |
