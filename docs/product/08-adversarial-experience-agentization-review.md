| | |
| --- | --- |

## 0. 结论

RefineQ 已经形成一条可信的学习闭环：用户目标和个人资料进入系统后，可以生成计划、按资料出题、结构化判分、更新掌握度、写入学习记录并安排复习。导航整治解决了此前最危险的结构性问题：同一对象不再分散在多套入口里，计划列表和日历共享操作语义，学习报告与原始记录边界清楚，跨空间日程能够回到正确的今日会话，跨区域切换和鉴权失效也不会静默遗失草稿或继续显示旧用户数据。

但产品还不是一个完整的“学习 Agent”。它目前更接近“可靠的学习工作流 + 可对话教练”：能响应用户操作，却还不能持续观察学习状态、解释下一步决策、在明确授权下执行和验证多步行动。最优先的下一步不是增加更多聊天能力，而是把现有闭环提升为一个可审计的决策循环：

> 观察证据 → 形成可纠正的判断 → 选择下一最佳行动 → 说明理由和预期收益 → 在权限内执行 → 验证结果 → 从接受、撤销和学习结果中校准。

## 1. 本次导航整治已经建立的基线

以下能力已落地，不再作为后续方案中的“待开发项”：

- 空间内一级导航收敛为“今日、计划、资料、进步”四项；旧路径会映射到新结构。
- 空间计划的列表 / 日历视图共享同一数据和完成、重开、改期、调时长、开始练习操作。
- 全局页面明确为“跨空间日程”，只做聚合和筛选；点击项目回到对应空间的今日计划会话。
- 今日页优先进入今天未完成或深链指定的计划会话；只有没有计划时才退回自由练习。
- 复习队列只在今日页出现；学习记录作为进步页内独立区块存在，不再与报告混成同一概念。
- 跨学习区切换保存练习模式、作答前掌握度、草稿和工作区快照；快照有版本和有效期并能安全处理存储配额错误。
- 上传或存在未提交草稿时，离开学习区会得到明确确认；浏览器前进 / 后退和组件卸载也会进行状态交接。
- 全局 `401` 会清空用户态缓存和本地学习状态并回到认证入口，避免跨账号泄漏旧界面数据。
- 高频只读请求有短时、用户隔离的 Promise 缓存；写操作会主动失效相关缓存；冷启动中独立请求并行执行。
- 管理设置存在未保存改动时，站内导航使用客户端跳转并保留离开确认。

## 2. 审查证据与边界

### 2.1 实际走查的关键旅程

1. 登录并进入空间，完成诊断，启动今日计划会话。
2. 查看资料引用，完成一次资料约束练习并进入结构化反馈。
3. 在移动端查看计划列表、日历入口和计划编辑器。
4. 在移动端查看学习报告，并直达独立学习记录。
5. 在桌面和移动端查看跨空间日程，并从日程回到具体今日会话。
6. 从共享外壳进入账户与安全页面。

### 2.2 证据限制

- 截图可以证明层级、密度、溢出和状态表达，不能单独证明读屏器语义、真实网络抖动或长时间使用效果。

## 3. 完整产品流程审查

| 1. 进入与认证 | 🟢 | 失效登录会不会继续展示旧账号数据？ | 全局 `401` 清理和回到认证入口已补齐；账户 / 管理也使用共享外壳。 |
| 2. 描述目标并路由 | 🟡 | 用户输入一句话后，能否知道系统理解了什么、为什么复用或新建空间？ | 路由结果存在，但“理解结果可修正”和“计划约束冲突”还不够显式。 |

| 8. 离开、恢复与异常 | 🟢 | 草稿、上传、身份失效、返回浏览器历史会不会造成静默丢失？ | 状态交接和离开确认覆盖了主要风险；仍需用故障注入覆盖配额、断网和多标签页。 |

### 3.1 流程级风险

#### P0 · 今日页存在两个“现在就做”的任务

当诊断尚未完成但用户已经进入练习时，诊断卡和练习区都占据高优先级和大面积空间。系统没有回答“诊断是当前必需、可以稍后补，还是已被练习证据替代”。这会延迟第一次真实作答，也会让用户怀疑诊断与掌握度之间的关系。

**解决原则：** 任一时刻只允许一个首要行动。诊断应成为有条件的步骤：没有足够证据时作为一次短校准；已有真实作答后，应允许跳过、折叠或只补未覆盖主题。

#### P0 · 计划约束可能出现互相矛盾的显示

目标文本、每日可用分钟数和计划会话编辑是不同更新路径。用户调整每日时间后，如果目标摘要仍保留旧数字，会出现“目标说 90 分钟、计划设置说 35 分钟”的可信度裂缝。对于计划型产品，数字冲突比一般文案错误更危险，因为它直接损害用户对排程结果的信任。

**解决原则：** 结构化约束是唯一事实来源。自然语言目标只作为原始输入保留；所有当前摘要从结构化字段生成，并标出“原始目标”和“当前计划约束”的区别。

#### P1 · 路由理解不可纠正

意图路由会产生空间、目标、截止日期和每日时间，但用户主要看到结果，缺少一次轻量的结构化确认。误判可能直到计划不合理时才暴露。

**解决原则：** 路由后展示一行可编辑理解摘要，例如“计算机组成原理｜10 月 25 日｜每天 90 分钟｜重点：流水线、缓存”，不增加向导页。

#### P1 · 跨空间日程在单空间阶段缺少独立价值

跨空间日程的职责已经清晰，但只有一个活跃空间时，它与空间计划高度重复。页面应说明“这是所有学习空间的负荷视图”，并在单空间时提供回到计划页的更直接选择，避免制造一份功能相同的第二日历。

## 4. 交互与视觉体验审查

### 4.1 信息层级

#### P0 · 两套日历的移动端策略不一致

跨空间日程并不是把七列月历压缩到手机宽度：在 `≤700px` 时，`.global-month-calendar` 开启横向滚动，并给周头和日期网格保留 `min-width: 720px`。用户必须横着拖动一张桌面月历。与此同时，空间计划日历在 `≤640px` 已经把网格改成单列、隐藏周头和空白日期，形成可线性浏览的议程。同一类对象在同一产品里采用两种移动端交互，会增加学习成本，也让跨空间视图显得像未完成的桌面移植。

**方案：** 直接复用空间计划日历现有的响应式规则和行式视觉：跨空间日程在窄屏移除 `720px` 最小宽度，隐藏周头与空白日期，按日期输出单列议程，并在每项补充空间名称；桌面继续保留七列月历。实现时抽取共享的“月历转议程”布局规则，避免两套断点再次漂移。

#### P1 · 移动端页面顶部占用过高

空间上下文标题、页面标题、工作区摘要和视图开关连续堆叠，用户滚动后才看到第一条计划或第一项结果。计划页尤其明显。

**方案：** 窄屏合并上下文标题与页面标题；空间摘要折叠为一行；首屏必须露出第一条可执行会话。

#### P1 · 当前空间与最近空间竞争注意力

侧栏同时展示当前空间卡和最近空间列表，长标题被截断后难以区分。当前空间应是上下文，不应与跳转列表拥有同样的视觉重量。

**方案：** 当前空间使用紧凑、不可误认的上下文条；最近空间只显示非当前项，标题提供完整可访问名称和悬停 / 聚焦提示。

#### P1 · 进步页展示结果，却没有把结果转成下一行动

学习报告和学习记录的边界已经清楚，但移动端报告很长，用户看完“最弱主题”后仍要自己寻找下一步。报告回答了“发生了什么”，没有直接回答“现在做什么”。

**方案：** 报告顶部增加唯一行动：“针对当前最弱主题开始 15 分钟练习”，并解释它如何影响计划；不再叠加更多指标卡。

### 4.2 状态和反馈

#### P0 · Agent 降级状态与可操作控件的外观可能冲突

当外部模型不可用时，界面提示本地学习仍可工作，但教练建议和输入区域仍可能呈现为可交互外观。用户会把“主闭环可用”误解为“教练也可用”。

**方案：** 分能力显示状态：练习、判分、检索、教练分别标识正常 / 本地降级 / 不可用。不可用的教练输入明确禁用并解释恢复方式；不要只给一个全局模型状态。

#### P1 · 忙碌态的对象粒度需要继续统一

计划会话已经有独立忙碌态，但跨页面的“正在上传、正在保存、正在路由、正在判分”仍需要同一语言：正在处理什么、是否可离开、失败后是否可重试。

**方案：** 建立四态组件规范：`idle → pending → success/error`，每个 pending 明确取消和离开策略，每个 error 提供就地重试且保留输入。

### 4.3 可访问性

当前键盘主导航、焦点和主要点击目标已有自动化覆盖，但完整可访问性仍不能仅靠这些测试下结论。优先补齐：

- 对日历和计划会话做读屏器线性顺序测试，不能只依赖视觉网格位置。
- 对状态变化使用合适的 live region，避免判分、保存成功只靠颜色和位置变化。
- 对截断标题提供可聚焦的完整名称。
- 用真实中英文长文本检查 200% 缩放，不把关键操作挤出视口。
- 跨空间日程移除横向拖动并复用单列议程后，保持不小于 44×44 CSS 像素的主要触控目标。

## 5. 价值实现四维审查

### 5.1 价值清晰度：🟢

首页和练习闭环已经能表达核心结果：把自己的资料变成练习，用可追溯证据判断掌握情况。它不是泛化的“AI 帮你学习”。

**尖锐问题：** 如果用户尚未上传资料，RefineQ 与通用聊天或普通题库的可感知差异还剩多少？

**守住的产品边界：** 无资料时可以提供诊断和计划，但必须把“上传资料后才能获得来源约束练习”说清楚，不能用泛化 AI 内容伪装核心价值。因此，资料可用性必须成为 `NextAction` 的前置门，而不是与学习任务平级的弱排序信号：没有可检索资料时，首要行动应是上传资料。

### 5.2 价值实现时间：🟡

理想路径可以在 5 分钟内到达第一次资料约束判分，但真实 PDF 解析、诊断竞争、路由修正和模型延迟都可能显著拉长。当前只有目标，没有生产分位数证据。

**尖锐问题：** 对真实用户的真实 PDF，而不是演示 TXT，首次资料约束判分的 P50 / P90 是否仍小于 5 分钟？

**应记录的关键时间点：** `intent_submitted`、`workspace_ready`、`first_material_searchable`、`first_question_started`、`first_grounded_grade_shown`。

### 5.3 价值感知：🟢

掌握度前后变化、结构化缺口、资料引用、复习时间和不可变学习记录让价值可见。产品已经能回答“这次练习让我知道了什么”。

**尖锐问题：** 用户能否在不解释产品机制的情况下，用进步页回答“我这周实际学会了什么、为什么相信这个判断”？

**待补环节：** 将“计划执行情况、掌握变化、下一风险”合成周度结果，而不是再增加一个总分。

### 5.4 价值发现：🟡

真正的 Aha 是第一次基于个人资料的判分，而不是空间创建、日历生成或教练对话。当前首次体验仍可能让诊断、计划和上传平均分配注意力。

**尖锐问题：** 新用户在第一次作答前，能否准确说出 RefineQ 的核心是“用我的资料考我并留下证据”，而不是“另一个学习聊天助手”？

**方案：** 首次路径只强调一条主线：说明目标 → 上传一份关键资料 → 完成一道资料约束题 → 看见掌握变化。计划和教练在首个 Aha 后渐进展开。

## 6. Agent 化对抗性审查

### 6.1 当前已经具备的 Agent 基础

- 有明确目标、截止日期、每日时间和主题等结构化约束。
- 有资料检索、来源引用和把上传内容视为不可信数据的安全边界。
- 有题目、作答、判分、掌握度、复习和计划等可执行的领域工具。
- 有服务端教练会话、幂等轮次和部分可执行建议。
- 有确定性降级，因此外部模型不可用时主学习闭环不会消失。
- 掌握度只由诊断和作答证据改变，没有把对话热度伪装成学习成果。

这些是比“增加一个聊天框”更重要的地基。

### 6.2 核心缺口

#### A0 · 没有显式的 Agent 决策对象

今天该做什么目前由页面和若干规则隐式决定。系统无法向用户或测试回答：触发条件是什么、使用了哪些证据、考虑过哪些替代项、预期收益是什么、何时应重新计算。

#### A0 · Agent 仍是响应式的

用户必须打开产品并触发动作。系统不会在资料解析完成、复习到期、连续错过计划或照当前速度无法按期完成时形成待处理建议。没有主动感知，就没有真正的持续代理关系。

#### A0 · 对话连续性没有成为服务端工作区事实

服务端保存教练会话，但当前活跃 `coachSessionId` 主要是客户端组件状态。跨学习区域卸载后可能开始新会话，用户感知为 Agent 忘记上下文。客户端快照已保存练习模式和掌握度基线，但尚未把教练会话交接纳入同一可靠性协议。

#### A1 · 用户看不到 Agent 的“信念”也无法纠正

系统掌握目标、弱项、截止日期和计划，但没有统一界面让用户看到“系统认为我现在的重点 / 限制 / 风险是什么”，更没有区分来源、置信度和最后更新时间。错误只能通过改多个页面间接修正。

#### A1 · 授权模型不完整

“回答问题、提出建议、修改计划、自动安排复习、以后主动提醒”风险不同。当前没有按工具定义的建议 / 需确认 / 可自动执行三级授权，也没有统一的操作日志、撤销和验证结果。

#### A1 · 缺少结果驱动的 Agent 评估

现有测试验证接口与流程正确性，但没有衡量 Agent 决策是否比简单基线更好：建议接受率可能高但学习收益低；自动调计划可能减少点击却增加撤销。不能用对话轮数或停留时长替代学习结果。

## 7. 从第一性原理推导方案

### 7.1 出发点

用户的根本任务不是“和 Agent 聊天”，也不是“维护一个漂亮计划”。用户要在有限时间内降低三类不确定性：

1. 我真正掌握了什么？
2. 在截止日前，现在做什么的收益最高？
3. 系统的判断和行动是否值得信任、可以纠正？

因此 Agent 的最小完整循环必须同时满足证据、决策、行动和验证：

```mermaid
flowchart LR
    O["观察：目标、资料、时间、计划、作答"] --> B["判断：掌握、置信度、进度风险、约束"]
    B --> D["决策：下一最佳行动与替代项"]
    D --> P["提议：理由、证据、预期收益、权限"]
    P --> E["执行：幂等、可审计、可撤销的工具"]
    E --> V["验证：状态差异与学习结果"]
    V --> L["学习：接受、撤销、纠正、实际效果"]
    L --> B
```

### 7.2 服务端 `NextAction` 决策对象

把今日页的主行动从前端条件分支提升为服务端领域对象：

```text
NextAction
  id / workspace_id / version / expires_at
  action_type: upload_material | start_review | start_session | repair_pace | start_practice
  trigger: material_missing | due_review | scheduled_session | weak_topic | pace_risk | material_ready
  preconditions: has_searchable_material 等可回放条件及其求值结果
  reason: 面向用户的一句话解释
  evidence_refs: 计划会话、作答、主题、资料等可追溯 ID
  expected_outcome: 预计用时与希望降低的不确定性
  alternatives: 至少一个可选行动和“稍后处理”
  tool_plan: 将调用的类型化工具及参数预览
  risk_level: low | medium | high
  approval_mode: advise | confirm | auto_safe
```

第一版不需要 LLM 决策。先执行资料门：工作空间没有任何可检索资料时，直接返回“上传一份资料”，不进入学习行动排序，也不生成通用模板题。资料可用后，再执行可解释、可回放的确定性策略：到期复习 > 今日指定会话 > 截止风险 > 最弱主题的资料约束练习。LLM 只负责把理由说得自然，不能改变门控、排序结果或伪造证据。等有真实事件后，再用离线回放比较新策略和基线。

### 7.3 “今日”升级为 Agent 决策收件箱

今日页首屏只展示一个主行动：

- 做什么：主题、活动和预计用时。
- 为什么现在做：使用的学习记录、截止日期和计划约束。
- 做完会改变什么：例如完成一项到期复习、验证某个弱项、降低进度风险。
- 可选项：换一个、调整时长、稍后处理。
- 自动行为：本次会写入哪些记录、是否会安排复习。

诊断、复习队列和教练都变成主行动的上下文或替代项，不再与它平级争夺首屏。

### 7.4 类型化工具、权限与操作日志

建立最小工具注册表：

| 工具 | 风险 | 默认权限 | 必备保护 |
| --- | --- | --- | --- |
| `start_session` | 低 | 自动 | 只读计划并生成幂等练习请求 |
| `queue_review` | 低 | 自动安全 | 仅追加、去重、不晚于考试日 |
| `schedule_session` | 中 | 确认 | 预览日期 / 时长冲突，可撤销 |
| `adjust_plan` | 中 | 确认 | 显示变更前后和受影响会话 |
| `search_material` | 低 | 自动 | 仅当前用户 / 空间，返回来源 |
| `save_question` | 低 | 自动 | 幂等、上限提示 |
| `change_goal_constraints` | 高 | 确认 | 版本检查、影响分析、明确二次确认 |

每次执行写统一操作日志：谁触发、依据、参数、幂等键、前后状态、结果、可否撤销。页面不要只显示“操作成功”，而要显示“Agent 将 3 个会话改期；2 个未变；计划风险由高降为中”。

### 7.5 可纠正的 Agent 记忆面板

为每个空间提供一张紧凑的“Agent 当前理解”：

- 目标与截止日期。
- 每日可用时间及临时例外。
- 当前弱项和置信度，附最近证据。
- 当前策略，例如“先补缓存，再复习流水线”。
- 未确认假设，例如“周末也可学习”。

每一项都能纠正、标记过期或删除；系统说明修改会影响哪些计划和建议。原始资料内容不是 Agent 指令，记忆条目必须来自受控字段或经过明确确认的推断。

### 7.6 主动触发，但不越权

先实现站内 Agent 收件箱，再考虑通知。允许产生建议的服务端事件：

- 资料解析完成，可以开始第一道资料约束题。
- 到期复习尚未完成。
- 连续错过计划，原计划已不现实。
- 按最近完成速度推算无法在截止日前覆盖重点。
- 新作答显著改变最弱主题或复习优先级。

只有低风险、可撤销动作可以在用户授权后自动执行。通知必须单独选择加入，支持安静时段、频率上限和一键退订。不要用焦虑文案制造回访。

### 7.7 连续性协议

将“当前教练会话”纳入服务端工作区状态或版本化快照：

- 空间重新挂载时恢复最近活跃、未结束的会话。
- 跨页面携带 `coach_session_id`，并校验用户与空间归属。
- 会话过期或不可恢复时明确说明开启新会话，不静默失忆。
- 多标签页使用服务端版本冲突提示，避免后打开的旧快照覆盖新状态。

## 8. 分阶段解决方案

### P0 · 建立可信的下一行动（1–2 周）

1. 实现带资料门的确定性服务端 `NextAction` 和决策理由；无可检索资料时唯一主行动是上传资料，今日页只渲染一个主行动。
2. 让诊断服从证据充分度：已有有效作答时折叠或按未覆盖主题补诊断。
3. 统一目标约束事实来源，消除自然语言目标与当前分钟数冲突。
4. 复用空间计划现有的移动端单列议程策略改造跨空间日程，桌面保留月历。
5. 补齐首次价值与回访启动的事件时间线，但不引入第三方分析 SDK。

**验收**

- 今日页在任一状态只出现一个主行动，并能展示可追溯理由。
- 无可检索资料时，`NextAction` 必须返回上传资料且不得进入通用模板题；资料可用后才执行学习任务排序。
- 同一快照输入总是产生同一 `NextAction`；资料门和任务排序都有表驱动边界测试。
- 诊断和练习不会同时作为首要任务出现；已有有效作答时诊断被折叠或仅补未覆盖主题。
- 修改每日分钟数后，所有当前摘要与排程一致，原始目标明确标注为历史输入。
- 390px 宽视口下，空间计划和跨空间日程都使用按日期排序的单列议程，不出现横向月历滚动；首屏能看见至少一条完整日程，主要触控目标不小于 44×44。
- 能计算首次资料约束判分 P50 / P90 与回访到开始练习 P50 / P90。

### P1 · 建立可授权、可纠正的 Agent 控制面（2–4 周）

1. 上线类型化工具注册表、按工具授权模式、变更预览、操作日志和撤销。
2. 增加 Agent 当前理解面板，支持纠正目标、约束、弱项解释和假设。
3. 增加错过计划与进度风险检测，Agent 提出可比较的重排方案。
4. 进步页增加一个由 `NextAction` 驱动的结果到行动入口。
5. 跨空间层提供真正的全局价值：负荷冲突、最紧迫截止和跨空间时间预算，而不只是另一张月历。
6. 持久化并恢复活跃教练会话；跨页面携带会话标识，并为恢复、过期和冲突增加自动化测试。

**验收**

- 所有 Agent 写操作都能追溯到决策、参数、结果和操作者。
- 中高风险动作未经确认不得执行；撤销后前后状态一致。
- 用户纠正一条 Agent 判断后，下一行动立即重新计算并解释变化。
- 重排方案展示“保持原计划”和“接受新计划”的截止风险差异。

### P2 · 经过评估后增加主动性（4–8 周）

1. 站内事件驱动的 Agent 收件箱和选择加入的通知。
2. 多步行动计划：例如“压缩本周低优先级内容 → 插入两次复习 → 周日验证”。
3. 离线策略回放、对抗样本、工具失败注入和学习结果评估。
4. 按真实数据决定是否需要更复杂的模型决策；不能证明优于确定性基线时不升级。

## 9. 评估体系与护栏

### 9.1 北极星不是活跃度

建议北极星改为完全由产品内事件计算的“资料约束学习闭环周完成率”：

> 当周完成至少一次“资料引用问题 → 提交作答 → 结构化判分 → 写入有效学习记录”完整闭环的学习者数 ÷ 当周进入过任一活跃学习空间的学习者数。

分子和分母都可由现有领域记录与事件时间线确定。它衡量核心价值是否真正完成，而不是打开次数或聊天轮数，也不会把产品内判分误当成外部学习真值。

“掌握度得到校准”不适合作为当前北极星：校准需要独立真值，而当前产品没有真实考试成绩、教师评分或其他外部结果来源。站内间隔复测只能作为学习保持的代理信号，不能自证掌握度模型准确。若未来允许用户选择性导入真实考试或教师评分，再把掌握度校准误差作为外部验证指标，并明确样本覆盖和选择偏差；在此之前不进入核心经营指标。

### 9.2 关键指标

| 类别 | 指标 | 目的 |
| --- | --- | --- |
| 时间 | 首次资料约束判分 P50 / P90 | 衡量首次价值实现时间 |
| 回访 | 打开到开始下一行动 P50 / P90 | 衡量 Today 是否真的减少选择成本 |
| 决策 | 下一行动接受、替换、稍后处理比例 | 判断策略匹配度，不单独追求接受率 |
| 安全 | Agent 动作失败率、撤销率、冲突率 | 发现越权或低质量执行 |
| 可信 | 记忆纠正率、理由展开率、来源查看率 | 判断用户是否理解和信任依据 |
| 计划 | 计划过期率、改期率、按期完成率 | 判断计划是否现实 |
| 学习 | 资料约束学习闭环周完成率、到期复习完成率、间隔复测表现变化 | 衡量闭环是否发生，并以站内代理信号观察保持情况；不声称等于外部掌握真值 |
| 主动性 | 通知退订率、忽略率、安静时段违规数 | 防止主动性变成骚扰 |

### 9.3 不可突破的护栏

- 不用聊天轮数、停留时长或连续签到代替学习结果。
- 不让 LLM 直接写掌握度；它只能提供结构化判分候选，领域规则决定是否形成证据。
- 不让上传资料成为 Agent 指令。
- 不在无解释、无日志、不可撤销的情况下自动改目标或大范围重排计划。
- 不用无法验证的“AI 预计提升”作为用户承诺。
- 不因为模型不可用而阻断确定性的学习主闭环。

## 10. 建议决策

1. 把 `NextAction` 视为下一阶段的核心领域对象，并把资料可用性设为前置门；没有资料时先上传，不生成低价值的通用练习。
2. Today 只承载一个首要行动；Plan 负责时间安排；Progress 负责结果和证据；Materials 负责来源；跨空间层负责资源冲突。保持职责互斥。
3. 先用确定性策略建立可解释基线，再评估 LLM 是否能在真实结果上增益。
4. 北极星只使用产品内可计算的闭环事件；没有独立真值前，不把掌握度校准误差当作可用指标。
5. 先做站内主动性和授权控制，再做外部通知。
6. 产品文档、事件模型和自动化测试必须与信息架构同时更新，避免实现已经变化而 PRD 仍描述旧 `/path` 模型。

这套方案的目标不是让 RefineQ “看起来更像 Agent”，而是让它在每一步都能回答：为什么这样判断、依据是什么、做了什么、结果怎样、用户如何纠正。
