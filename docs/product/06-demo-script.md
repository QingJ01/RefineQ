# 演示与路演脚本

覆盖四个场景：动态测评（平台自动验证）、2 分钟视频、4 分钟路演、现场故障预案。所有演示都基于同一套预置数据，先做第 1 节。

## 1. 演示数据准备

### 1.1 预置账号

```powershell
# 在部署环境执行，幂等可重复
$env:REFINEQ_DEMO_EMAIL = "learner@refineq.local"
$env:REFINEQ_DEMO_PASSWORD = "运行时临时强密码"
refineq-demo
Remove-Item Env:REFINEQ_DEMO_PASSWORD
```

得到演示账号 `learner@refineq.local`（密码仅由运行时环境提供，源码和命令输出均不包含密码），内含空间
`refineq-demo`：已有资料、诊断、计划与一次作答记录，保证评审打开就有内容可看。这些内容仅是演示夹具，
不得作为真实用户、访谈或参赛证据。

### 1.2 手工演示空间（用于视频与路演）

预置数据证明"有积累状态"，但视频要展示"从零开始"的过程，两者用途不同：

1. 新建一个干净演示账号（与管理员、seed 账号都分开）。
2. 准备去敏资料 1–2 份：10 页以内的 PDF 讲义 + 一份 Markdown 笔记，内容来自起点人物真实科目（已授权、已去敏）。
3. 预演一遍意图句式（考试 + 日期 + 每日分钟），确认路由结果与计划符合预期。
4. 录制前重置：删掉演示空间重来，保证录屏里的路由通知、计划生成都是首次效果。

### 1.3 响应时间预算（动态测评自查）

提交前在公网环境逐项实测，超预算的项优先排查：

| 操作 | 预算 | 备注 |
| --- | --- | --- |
| 冷启动首页 | < 5 s | 容器常驻，避免冷启动；提交当天保持实例活跃 |
| 登录 | < 1 s | |
| 意图 → 空间 + 计划 | < 8 s | AI 路由含一次模型调用；降级路径 < 1 s |
| 上传 10 页 PDF → 可检索 | < 15 s | 含分块与向量化 |
| 出题（AI） | < 15 s | 降级 < 1 s |
| 判分（AI） | < 15 s | 降级 < 1 s |
| Agent 对话 + 动作提案 | < 20 s | 动作抽取独立 8 s 预算；失败时仍返回文字回复 |
| 教练换题动作 | < 15 s | 动作卡先出现，题目区独立加载；改期 / 收藏 < 1 s |

对齐官方建议结构（HACKATHON.md 第 15 节）。台词提前写好读熟，画面全部真实录屏。【】内待访谈后填写。

| 时间 | 画面 | 台词要点 |
| --- | --- | --- |
| 0:00–0:15 | 人物侧写（照片或文字卡，已授权） | "这是【化名】，【身份】，【日期】考【考试】。TA 有 27 份课件和两本笔记，但没法判断自己到底掌握没掌握。" |

| 0:45–1:05 | 拖入 PDF → 解析完成 → 搜索一个概念 → 命中资料原文 | "上传 TA 自己的讲义。之后所有题目和回答，都会引用这些资料，而不是通用题库。" |

## 3. 动态测评连通性清单

平台会解析源码或直接调用，确保以下事实成立：

- 体验链接裸访问可用：无需 VPN、无需白名单、手机流量可开。
- 首页未登录状态可以注册，注册无邀请码。
- README 根目录版含：体验链接、演示账号、启动方式、架构图、环境变量表（这几项当前 README 已有大半，提交前补演示账号一节）。
- ZIP 内不含 `.env`、密钥、`data/`、`node_modules`、`.venv`、`.next`（打包命令见 [07-submission-kit.md](07-submission-kit.md)）。
- 健康检查 `/health/live`、`/health/ready` 公网可达（平台可能探测）。

## 4. 四分钟路演（复赛）

时间分配对齐评分权重：人物与问题 1 分钟（30%），现场演示 2 分钟（40%），真实使用与反馈 45 秒（20%），技术与可靠性 15 秒（10%）。

1. **0:00–1:00 人物与问题。** 讲【化名】的具体处境，引一句原话，用竞品差距表回答"为什么现有产品不够"。不提功能列表。
2. **1:00–3:00 现场演示。** 按视频 0:30–1:50 的动线现场操作（备份视频待命）。关键动作旁白："注意题目下面的引用，来自 TA 自己的讲义第 14 页。"
3. **3:00–3:45 真实使用。** 首次任务耗时、练了几题、发现的薄弱点、TA 最具体的一条反馈、我们改了什么、二次使用的变化。
4. **3:45–4:00 完成度与边界。** "公网可用，AI 不可用时练习和记录照常工作。我们只服务有资料、有截止日期的备考者，这是刻意的。"

六页 PPT 与官方建议一一对应（HACKATHON.md 第 16 节），每页只放一个论点 + 一张截图或一条原话。

### 4.1 教练动作镜头（复赛版）

在现场演示的练习段加入一句自然请求：`这题太难了，换一道简单点的。` 画面应同时保留教练回复与动作卡，随后只让题目区进入加载态并自动换题，不跳页面、不再点击按钮。旁白强调："它不只建议我去点哪里，而是把明确意图变成经过当前学习状态校验的动作。"

预演时分别验证两条分支：

1. **主镜头，无草稿。** 空答案时发出请求，动作直接执行；卡片显示主题、难度和已执行状态，新题同步出现。
2. **安全分支，有草稿。** 先输入一小段答案再请求换题；卡片必须提示草稿会被清空，点击“继续执行”后才换题。录制主视频只用第一条，答辩追问安全边界时展示第二条。

改期与收藏可作为备用口令：`把明天的复习挪到周六`、`这题帮我收藏`。动作是否成功只看动作卡和对应界面更新，不把教练文字当成成功证明。

## 5. 故障预案

| 现场状况 | 动作 | 话术 |
| --- | --- | --- |
| 模型超时 / 报错 | 继续操作，不刷新重试超过一次 | "外部模型刚好抖动——可以看到系统降级成确定性出题，学习记录完全不受影响。这是我们刻意设计的：AI 是增强，不是单点。" |
| 会场网络断 | 切换手机热点；再不行放备份视频 | 提前把备份视频存本地两份（电脑 + 手机） |
| 演示账号状态被讲乱 | 用第二个预演过的备份账号 | 两个演示账号提交前都各自完整预演一遍 |
| 上传卡住 | 跳过上传，用已预置资料的空间继续 | "资料我提前传好了，我们直接看它怎么用这些资料出题。" |
