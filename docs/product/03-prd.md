## 1. 术语表

| 术语 | 定义 |
| --- | --- |
| 学习空间 | 一个学习方向的私有容器，聚合目标、主题、资料、计划、练习与证据。用户不手动创建，由意图路由产生 |
| 意图 | 用户描述学习目标的一句自然语言，1–2000 字符 |
| 路由 | 把意图解析为"新建 / 复用 / 切换"某个学习空间的决策，附理由与置信度（0–1） |
| 主题 | 空间内的知识单元，带知识类型（记忆 / 概念 / 程序 / 设计），每空间 1–200 个 |
| 掌握度 | 某主题"已掌握"的后验概率（BKT 模型），取值 0–1，仅由作答与诊断证据更新 |
| 难度状态 | 每主题独立的 1–5 级出题难度，随对错自适应调整 |
| 学习模式 | 出题与教练的风格取向：概念理解 / 案例分析 / 项目实践 / 考试冲刺 |
| 诊断 | 一组按主题的初始自评（对 / 错），用于建立掌握度基线 |
| 证据 | 一次诊断或作答的不可变记录，含时间、主题、结论与判分详情 |
| 计划会话 | 计划中的一个学习时段：主题、日期、分钟数、活动类型（学习 / 复习）、状态（计划中 / 已完成） |
| 复习注入 | 作答后自动向计划插入复习会话的机制 |
| 降级模式 | 外部 AI 不可用时的确定性替代路径；产出物带 `mode: fallback` 标注 |
| 幂等键 | 客户端生成的去重标识：出题 `request_id`、作答 `attempt_id`、对话 `turn_id` |
| 快照 | 打开空间时一次性返回的全量状态：空间、进度、计划、证据、资料、收藏题、待答题、上次判分 |

## 2. 背景与问题

【化名】在准备【具体考试】（人物档案见 [02-persona.md](02-persona.md)）。TA 手里有老师的课件、自己的笔记和历年题，但这些资料在网盘里躺着；TA 用 AI 问过问题，当时觉得懂了，几天后做题还是不会。离考试越近，越说不清自己到底掌握了多少。

问题的本质是资料与掌握判断之间断了链：没有工具持续拿"TA 自己的资料"出题、判分、记录薄弱点。现有产品各管一段——聊天机器人不记得资料，题库 App 没有 TA 这门课，网盘和计划表不管"学会没有"（逐项对比见 [01-positioning.md](01-positioning.md) 第 3 节）。

**问题陈述：** 对一个有自己资料、有截止日期的备考者，没有一个工具能把"我的资料"持续变成"我的练习"，并用证据回答"我掌握了没有"。

**解决方案概述：** RefineQ 用一条不可跳步的闭环回应这条需求：

```
说明目标 → 自动进入学习空间 → 上传个人资料 → 形成计划
→ 主动练习 → 智能判分 → 记录证据 → 根据薄弱点继续练习
```

## 3. 产品目标与成功指标

三个产品目标：

1. **一句话就能开始。** 说明目标后，空间、主题、到考日的计划一步到位；用户全程没有"建项目、配模型"这类管理动作。
2. **一切以用户自己的资料为依据。** 题目从资料生成并标注原文出处，判分与教练回答引用资料佐证，引用可点开验证。
3. **掌握度可信。** 只有构成证据的作答能改变掌握度，每次变化可追溯到台账里的一条记录。

| # | 指标 | 定义 | 目标 | 度量方式 |
| --- | --- | --- | --- | --- |
| M1 | 首次价值时间 | 新用户从注册到看到第一次判分的耗时 | ≤ 5 分钟 | 真实使用观察（v1 手工计时，见 §10） |
| M2 | 闭环完成率 | 起点用户无协助走完八步核心体验 | 100% | 观察记录 |
| M3 | 判分可解释 | 判分含分数、通过、优势、缺口、误区、引用六要素 | 100% | 契约测试 |
| M4 | 降级可用 | 外部 AI 不可用时练习与记录照常工作 | 100%，零丢失 | 集成测试 + 演练 |
| M5 | 真实使用 | 目标用户完整使用并在修改后复访 | ≥ 1 人两次 | 使用记录 |
| M6 | 回访效率 | 老用户打开到进入"今天该做的事" | ≤ 30 秒 | 观察记录 |

反向护栏（不为冲指标而破坏的底线）：不虚增掌握度（聊天、浏览不计入）；不为速度砍掉判分要素；不为演示预置假证据。

## 4. 目标用户与场景

### 4.1 用户画像摘要

| 维度 | 特征 |
| --- | --- |
| 处境 | 有明确考试或能力目标，截止日期已定，每天可用时间有限（典型 30–120 分钟） |
| 资产 | 有公共题库覆盖不到的个人资料：讲义 PDF、笔记、历年题，通常 10–50 份 |
| 缺口 | 需要确认"是否真正掌握"，而不是获取更多解释 |
| 工具史 | 用过通用 AI 问答、网盘、题库 App，各解决一段，链路没人接 |
| 设备 | 桌面为主，手机查看为辅 |

起点人物完整档案与访谈来源见 [02-persona.md](02-persona.md)。

### 4.2 场景一 · 首次会话

周五晚上，TA 注册后在首页输入："10 月 25 日考计算机组成原理期中，每天能学 90 分钟，先补流水线和缓存。"系统建立"计算机组成原理"空间，识别出考试日期与每日时间，当场生成到考日的计划，并说明为什么建了新空间。TA 把 27 份课件里最重要的 3 份拖进资料页，两分钟后从今日页点开第一道题——题面下方就是课件第 14 页的原文引用。作答提交，判分卡显示 62 分：概念对了，两个缺口，一个误区，"缓存一致性"掌握度从 35% 变为 41%，明天有一场 30 分钟复习已排进计划。整个过程不到 5 分钟（逐步交互见 [04-experience.md](04-experience.md) 第 1.1 节）。

### 4.3 场景二 · 第 N 天回访

周三午休，TA 打开 RefineQ，直接落在上次空间的今日页：今天计划两个会话，其中一个是前天答错内容的复习。TA 点开继续，上次没答完的题还带着草稿。30 秒内进入正题（见 [04-experience.md](04-experience.md) 第 1.2 节）。

### 5.1 页面清单

| 路由 | 页面 | 主要内容 | 必备状态 |

### 5.2 权限矩阵

| 操作 | 游客 | 学习者 | 管理员 |
| --- | --- | --- | --- |
| 注册 / 登录 / 找回密码 | ✓ | — | — |
| 意图路由、空间管理、资料、练习、计划、教练 | — | ✓（仅本人数据） | ✓（仅本人数据） |

### 5.3 平台与语言

响应式 Web（桌面优先，手机可完成核心闭环）；界面中英双语可切换；无原生 App（见 §12 范围外）。

## 6. 功能需求

优先级：P0 = 缺了产品不成立；P1 = 显著增强，可后置。每条需求附业务规则与验收标准；流程只列主干与关键分支。

### A · 目标与学习空间

> 作为备考者，我说一句"10 月 25 日考计算机组成原理期中，每天能学 90 分钟"，就得到这门考试自己的空间和到考日的计划，不需要建项目、填表单。

**需求**

- **FR-A1（P0）意图理解。** 系统从一句话中识别学习方向、考试日期、每日可用时间。规则：意图 1–2000 字符；日期缺省为 7 天后；每日时间缺省 45 分钟，接受 5–480 分钟。
- **FR-A2（P0）路由决策。** 对每条意图给出三种动作之一：新建空间、复用当前方向、切换到已有方向；返回置信度与一句话理由。低信息输入（"继续""随便学点"）复用最近活跃空间。AI 路由不可用时走确定性关键词匹配，行为不变。
- **FR-A3（P0）空间即备好。** 新空间创建与主题初始化、计划生成在同一事务内完成；任何一步失败整体回滚，不留半成品空间。
- **FR-A4（P0）路由透明与撤销。** 路由结果以通知条呈现（动作、理由、置信度），7 秒自动收起；期间可一键撤销回到原空间。
- **FR-A5（P0）空间管理。** 空间可重命名、归档、恢复、删除（删除需确认）；上限 100 个 / 人；列表默认隐藏已归档。

**主流程（新建）**：输入意图 → 解析约束 → 路由决策 → 建空间 + 播种主题（每主题初始化掌握度与难度）+ 生成计划 → 跳转今日页 + 路由通知。
**关键分支**：命中已有空间 → 恢复该空间快照并说明"为什么带你来这里"；配额满 → 明确报错，提示归档或删除；意图为空 → 前端拦截。

**验收**

1. 输入示范句，AI 可用时 8 秒内出现空间与到考日的完整计划。
2. 同一目标换说法再提交，路由到同一空间而不是重复新建。
3. 撤销后回到此前空间，通知不再出现。
4. 关闭外部模型重复以上三条，行为一致（理由文案不同）。

### B · 个人资料库

> 作为用户，我把讲义丢进去，之后的题目和回答都能指回这些资料的原文。

**需求**

- **FR-B1（P0）上传与解析。** 支持 PDF、DOCX、TXT、Markdown；文字类本地解析，不依赖外部服务。规则：单请求 ≤ 52 MB；单用户 ≤ 500 份、总量 ≤ 2 GB；PDF ≤ 500 页；DOCX 解压 ≤ 100 MB 且压缩比 ≤ 100（防 zip 炸弹）；单文件提取 ≤ 200 万字符、超时 15 秒；上传并发全局 2、单用户 1，正文空闲超时 10 秒、总超时 60 秒。
- **FR-B2（P0）扫描件识别。** 管理员启用 OCR 后，无文字页分批送视觉模型：每次 ≤ 50 页、每请求 ≤ 4 图，单页 ≤ 1200 万像素、累计 ≤ 8000 万像素、单图 ≤ 40 MB。混合 PDF 只送无文字页。
- **FR-B3（P0）检索与溯源。** 资料分块索引，语义（向量）与关键词混合排序；Embedding 不可用时降级纯关键词。每条结果显示原文片段与来源文件名；历史资料的缺失向量在启用 Embedding 后后台补齐。
- **FR-B4（P0）管理与隔离。** 列表、搜索、下载原件、删除（连带索引）；资料严格属于空间主人，跨用户表现为不存在。

**主流程（上传）**：选择 / 拖入文件 → 类型与大小校验 → 解析提取 →（无文字页且 OCR 启用 → 分批识别）→ 分块 →（Embedding 可用 → 向量化）→ 入索引 → 列表更新。
**关键分支**：解析失败 → 该文件标记失败并给出原因，不影响同批其他文件；配额超限 → 上传前拒绝并显示当前用量；上传中可取消。

**验收**

1. 上传 10 页文字 PDF，15 秒内可检索到其中概念，结果含原文片段。
2. 上传超限文件，得到明确的规则说明而不是通用错误。
3. 另一账号访问该资料的任何接口均为 404。
4. 关闭 Embedding，检索仍返回关键词结果。

### C · 学习计划

> 我要一份到考试日为止、按我每天时间排的计划，练错了的内容它自己安排复习。

**需求**

- **FR-C1（P0）计划生成。** 按截止日期、每日分钟数、主题列表生成会话序列，每会话含主题、日期、分钟数、活动类型。
- **FR-C2（P0）复习注入。** 作答后自动插入复习会话：答对排 3 天后、答错排次日，时长为 min(30, 每日分钟数)，不排在考试日之后；同一次作答不重复注入。
- **FR-C3（P0）会话操作。** 标记完成、重开、改期（必须带时区）、调整分钟数、从会话一键进入对应主题练习；操作中该会话显示独立忙碌态，不锁整页。
- **FR-C4（P0）等价双视图。** 列表与日历必须共享同一计划数据和同一套会话操作；切换视图不丢失当前空间与待保存状态。
- **FR-C5（P0）跨空间日程。** 全局日程只负责聚合与筛选，不复制空间内的计划编辑器；点击项目进入对应空间的今日页并带上计划会话标识。

**验收**

1. 新空间创建即有计划，会话总时长与"每日分钟 × 剩余天数"数量级一致。
2. 答错一题后，计划次日出现该主题复习项；重复提交同一作答不再新增。
3. 改期后列表与日历立即重排，完成 / 重开状态在两种视图一致。
4. 从跨空间日程点击一项，落到正确空间、正确计划会话，不落入另一套练习入口。

### D · 主动练习与判分

> 我不想自己找题。系统主动考我最弱的地方；判分要告诉我差在哪，而不是只给一个分数。

**需求**

- **FR-D1（P0）主动出题。** 默认选当前掌握度最低的主题；可指定主题、难度（1–5）与学习模式（概念 / 案例 / 项目 / 考试）。AI 出题基于资料检索并附引用；AI 不可用时出确定性题目，同样可判分。
- **FR-D2（P0）待答题唯一。** 每空间同时只有一道待答题；显式"换一题"才替换；切换学习模式时当前题按新模式重出。
- **FR-D3（P0）题目生命周期。** 出题幂等（`request_id` 重放同一题）；历史题保留 200 道 / 空间，收藏题（上限 100）不被淘汰；收藏可随时取消。
- **FR-D4（P0）结构化判分。** 输出分数（0–100）、是否通过、优势、缺口、误区、资料引用六要素；作答 1–10000 字符。AI 判分不可用时降级为要点覆盖率判分，六要素仍齐备（内容较简）。
- **FR-D5（P0）证据驱动掌握度。** 仅当判分认定"构成掌握证据"时更新该主题掌握度（BKT）与难度状态；判分同时生成证据记录。教练聊天、看题、浏览不改变掌握度。
- **FR-D6（P0）变化即时可见。** 判分卡同屏显示该主题掌握度变化（作答前 → 作答后）与下次复习时间。
- **FR-D7（P0）作答幂等与草稿。** `attempt_id` 去重，重复提交返回原判分（标注重放）；未提交草稿按题保存在本地，刷新后恢复；判分后草稿清除。

**主流程（一次练习）**：点开始 → 选题（幂等检查 → 待答题优先 → 按掌握度选主题 → AI / 降级出题）→ 展示题目与引用 → 作答 → 提交（幂等检查 → 判分 → 更新掌握度与难度 → 写证据 → 注入复习 → 清待答题）→ 判分卡。
**关键分支**：指定了不存在的主题 → 明确报错；判分途中断网重试 → 命中 `attempt_id` 返回原结果，不重复计分；历史满且全是收藏题 → 提示清理收藏。

**验收**

1. 连续两次提交同一 `attempt_id`，只产生一条证据，第二次响应标注重放。
2. 判分卡六要素齐备，掌握度变化与台账记录一致。
3. 降级模式下题目与判分带 `fallback` 标注，闭环完整可走。
4. 刷新页面后未提交的草稿仍在；判分后草稿消失。
5. 收藏一道题，再连续出题 200 次，收藏题仍可回看。

### E · 进步与证据

> 我要能看到每个主题掌握到什么程度、判断依据是什么，而不是一个笼统的百分比。

**需求**

- **FR-E1（P0）掌握全景。** 各主题掌握度可视，显示可读主题名（不是内部 ID）；薄弱主题一键发起定向练习（可带难度）。
- **FR-E2（P0）学习记录。** 以独立区块逆序展示全部证据：时间、类型（诊断 / 作答）、主题、结论、判分摘要；记录不可编辑、不可删除，报告区提供可见的直达入口。
- **FR-E3（P0，v1.2）学习报告卡。** 汇总考试倒计时、累计练习数、通过率、进步最大主题、当前最弱主题；数据全部来自现有快照。

**验收**：任意一次掌握度变化在台账中可找到对应记录；从薄弱点入口出的题属于该主题。

### F · 学习教练对话

> 我随时提问，它应该知道我的目标、进度和资料，而不是从零开始的通用聊天。

**需求**

- **FR-F1（P0）上下文自动携带。** 每轮对话自动注入：目标、计划、各主题掌握度、按问题检索的资料（最多 6 条）；练习中提问再附当前题目、草稿与判分反馈，教练按"学习 / 练习 / 反思"阶段调整回应。
- **FR-F2（P0）引用受控。** 回答只允许引用服务端候选资料，越界引用标记被剥除；引用可点开原文。
- **FR-F3（P0）注入防护。** 资料与学习状态作为不可信数据注入，其中的指令性内容不被执行；系统提示词不因资料内容改变。
- **FR-F4（P0）会话管理。** 会话按空间隔离，可列出、回看、删除；单用户 ≤ 200 个会话；每会话保留最近 20 条消息（40000 字符内），单条消息 ≤ 20000 字符，回复 ≤ 20000 字符；`turn_id` 幂等，重试不产生重复消息。

**主流程**：提问 → 组装上下文（状态 + 检索）→ 模型调用（30 秒超时，重试 2 次）→ 引用过滤与清洗 → 存会话 → 呈现回答与来源。
**关键分支**：新会话且配额满 → 明确报错；会话属于另一空间 → 拒绝；模型失败 → 报错但历史不丢。

**验收**

1. 教练回答中的每个引用都能点开对应资料原文。
2. 在资料中埋入"忽略以上指令"类文字，系统行为与提示词不变。
3. 同一 `turn_id` 重发，会话中不出现重复消息。

### G · 账号与管理后台

- **FR-G1（P0）账号体系。** 邮箱注册、登录、退出、密码找回（重置令牌 20 分钟有效、一次性）；认证接口限流 30 次 / 分钟，写操作 240 次 / 分钟。
- **FR-G2（P0）集中配置。** 管理员统一配置模型、Embedding、OCR、对象存储四类集成；密钥加密落库、界面只回显掩码；每类支持服务端连通性测试并记录最近测试结果；外部域名需在部署 allowlist 内，请求前复核 DNS/IP，默认拒绝内网与保留地址。
- **FR-G3（P0）用户零配置。** 普通用户全程不接触任何 API Key；管理员账号与演示账号分离。
- **FR-G4（P0）审计。** 集成配置的每次修改与测试记录操作者与时间。

**验收**：普通账号访问管理接口得到权限错误；配置测试能区分成功、鉴权失败、网络不通；密钥保存后任何接口不再返回明文。

## 7. 非功能需求

- **NFR-1（P0）性能预算。** AI 可用：意图到空间 ≤ 8 秒、出题 / 判分各 ≤ 15 秒、教练回复 ≤ 20 秒、10 页 PDF 到可检索 ≤ 15 秒；降级路径 ≤ 1 秒；冷启动首页 ≤ 5 秒。完整表见 [06-demo-script.md](06-demo-script.md) 第 1.3 节。
- **NFR-2（P0）可降级。** 路由、出题、判分、检索四处 AI 依赖全部有确定性替代；降级期间学习记录零丢失；产物带模式标注（界面提示 v1.1 补足）。
- **NFR-3（P0）安全与隐私。** 数据按用户隔离，越权表现为不存在；密码 bcrypt、密钥 Fernet 加密；外部端点 SSRF 防护；上传内容不作为指令执行；源码与日志不含明文密钥。
- **NFR-4（P0）幂等与一致性。** 三类写操作幂等；存储写入原子（SQL 乐观版本 + 所有者锁 / 本地原子替换）；并发冲突返回明确错误而不是静默覆盖。
- **NFR-5（P0）可观测与运维。** 提供存活 / 就绪健康检查；支持备份与恢复；SQLite（开发）与 PostgreSQL + pgvector（生产）双拓扑，迁移有工具与测试。
- **NFR-6（P1）无障碍与响应式。** 键盘可完成核心闭环；状态变化有 aria 播报；手机端可走通八步。

## 8. 数据模型（概念）

| 实体 | 关键属性 | 关系 |
| --- | --- | --- |
| 用户 | 邮箱、显示名、角色（学习者 / 管理员） | 拥有以下全部实体 |
| 学习空间 | 标题、学科、目标、主题列表、关键词、最近活跃时间、归档标记 | 1 用户 → N 空间 |
| 主题 | 名称、知识类型（记忆 / 概念 / 程序 / 设计） | 1 空间 → 1–200 主题 |
| 掌握状态 | BKT 后验概率及模型参数 | 每主题一份 |
| 难度状态 | 当前级别 1–5、近期对错窗口 | 每主题一份 |
| 资料 | 文件名、类型、大小、状态、分块数、内容指纹、存储位置 | 1 空间 → N 资料 |
| 资料分块 | 序号、文本、向量（可空） | 1 资料 → N 分块 |
| 题目 | 题面、期望答案、难度、模式、引用、生成方式（ai / fallback） | 空间内历史 ≤ 200 |
| 证据 | 类型、来源 ID、时间、结论、判分详情 | 只增不改 |
| 计划 | 会话列表（主题、时间、分钟、活动、状态） | 每空间一份 |
| 教练会话 | 消息序列（角色、内容、引用）、幂等轮次表 | 1 用户 ≤ 200 会话 |
| 集成配置 | 类型、启用态、配置、加密密钥、最近测试结果 | 全局，每类型一份 |

## 9. 错误处理与文案规范

**原则**：每个错误带稳定错误码与一句可执行的人话；可恢复错误提供当场重试；错误呈现用横幅或就地提示，可关闭；表单校验错误落在字段旁而不是全局横幅。

| 错误码（示例） | 场景 | 用户视角处理 |
| --- | --- | --- |
| `workspace_not_found` | 空间不存在或无权访问 | 恢复页：提示不可用，提供重试与返回主页 |
| `workspace_quota` | 空间达 100 上限 | 提示归档或删除后重试 |
| `invalid_learning_constraints` | 意图约束不成立（如日期已过） | 提示修改意图中的时间信息 |
| `learning_not_seeded` | 空间学习状态缺失 | 引导重新发起目标 |
| `learning_conflict` | 主题不存在、题目非待答等冲突 | 说明冲突原因，刷新当前状态 |
| `agent_session_limit` | 会话配额满 | 提示删除旧会话 |
| `rate_limited` | 触发限流 | 提示稍后再试，不清空已填内容 |
| 网络 / 超时 | 请求失败 | 保留输入与草稿，提供重试；作答重试走幂等键 |

降级不是错误：AI 不可用时不弹错误横幅，流程继续，产物标注降级来源（v1.1 起界面可见）。

## 11. 依赖与假设

- 管理员已在后台完成模型与 Embedding 配置；未配置时产品以降级模式运行（可用但体验降档）。
- 外部模型服务按 OpenAI 兼容协议提供，域名已加入部署 allowlist。
- 生产拓扑为 Docker Compose：PostgreSQL 17 + pgvector、API、Web、Caddy；对象存储默认本地卷，可切 S3 兼容服务。
- 用户资料有权上传（用户自查），平台按不可信数据处理并做访问隔离。

## 12. 范围外

以下明确不做，与"刚好够用"的定位一致：

- 通用全能助手与闲聊陪伴。
- 公共题库、刷题社区、排行榜与社交。
- 课程内容生产——用户的资料就是教材。
- 多人协作与教师端。
- 本阶段不做：原生 App、推送通知、音视频资料解析、第三方分析 SDK。
