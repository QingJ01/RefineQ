# 起点人物与场景洞察

洞察与理解占复赛评分 30%，官方判断标准是：人物真实具体、需要来自观察或亲身经历、找到了现有产品未满足的需要。这份文档提供访谈、授权和叙事的全部工具。**所有【待访谈填写】字段必须来自真实访谈，虚构即取消资格。**

## 1. 起点人物档案（模板）

| 字段 | 内容 | 来源要求 |
| --- | --- | --- |
| 化名 | 【待访谈填写】 | 征得本人同意的化名 |
| 身份背景 | 【待访谈填写】年级/专业/职业 | 访谈 |
| 正在准备的考试 | 【待访谈填写】具体到科目和考试名称 | 访谈 |
| 截止日期 | 【待访谈填写】具体日期 | 访谈 |
| 每日可用时间 | 【待访谈填写】分钟数，区分工作日/周末 | 访谈 |
| 资料形态与数量 | 【待访谈填写】如"教师课件 PDF 约 30 份、手写笔记扫描件、历年题 Word" | 访谈，最好当场看一眼 |
| 当前学习方法 | 【待访谈填写】TA 现在一天怎么学 | 访谈 |
| 最费力的环节 | 【待访谈填写】用 TA 自己的话记录 | 访谈原话 |
| 用过的工具及落空之处 | 【待访谈填写】逐个工具问"后来为什么不用了" | 访谈 |
| 授权范围 | 【待访谈填写】见第 3 节 | 签署确认 |

选人建议：优先选身边真实备考的人（同学、朋友、家人），科目冷门反而有利，因为"题库 App 没有我这科"是最硬的差异化证据。

## 2. 访谈提纲（30–40 分钟）

按顺序问，重点不是确认 RefineQ 有用，而是听 TA 怎么描述自己的困难。全程录音或逐字记录，原话之后要直接引用。

开场（5 分钟）：
1. 你现在在准备什么考试？什么时候考？这次考试对你意味着什么？
2. 一天里你什么时候学这门课？能坚持多久？

资料与方法（10 分钟）：
3. 你手里有哪些资料？存在哪？（请 TA 打开给你看）
4. 这些资料你实际会翻开的有多少？剩下的为什么不看？
5. 你怎么判断一块内容"已经会了"？上一次这么判断是什么时候？

工具史（10 分钟）：
6. 备考过程中用过哪些 App 或 AI 工具？各用来干什么？
7. 有没有用 ChatGPT 之类的问过问题？问完之后发生了什么？（追问：过几天还记得吗？后来做题会了吗？）
8. 哪个工具你已经不打开了？那一天发生了什么？

困难定位（10 分钟）：
9. 备考里最让你心里没底的是什么？
10. 如果考前一周有人告诉你"你这三块还不行"，你希望 TA 怎么得出这个结论？

结束（5 分钟）：
11. 说明 RefineQ 想解决什么，邀请 TA 在提交前完整用一次（见第 5 节），确认授权范围。

**访谈后 24 小时内**整理出：3 条以上原话引语、一份按档案模板填写的画像、TA 现有资料的类型清单。这些直接进入路演第 1 页和视频前 15 秒。

## 3. 授权确认（模板）

轻量书面确认即可，微信文字确认也算数，留存截图：

> 我同意 RefineQ 团队在 Eazo 黑客松参赛材料（提交表单、演示视频、路演 PPT）中使用：①我的化名与备考背景描述；②我在访谈中的原话引语；③我使用 RefineQ 的过程记录与反馈（截图中的姓名与文件名会做遮挡处理）。我知悉可以随时要求撤回上述内容。

涉及 TA 上传的真实资料时，演示与截图一律使用去敏副本，文件名和内容不出现真实姓名、学校、学号。

## 4. 官方六问回答框架

提交表单和路演都会被对照这六问审。每问给出回答结构，证据列必须能指向一份真实记录。

| 问题 | 回答结构 | 证据 |
| --- | --- | --- |
| 1. 从谁开始创作？ | 化名 + 身份 + 具体考试 + 截止日期 | 访谈记录 |
| 2. 什么场景遇到什么问题？ | 一段场景白描：TA 在哪、面对什么资料、卡在哪一步。用原话结尾 | 访谈原话 |
| 3. 为什么现有产品不够？ | 用 TA 的工具史回答，对照 [01-positioning.md](01-positioning.md) 第 3 节竞品差距表 | 访谈第 6–8 题 |
| 4. Agent 如何进入真实生活？ | 完整闭环：说目标→空间→资料→计划→练习→判分→证据→下一步 | 产品本身 + 使用记录 |
| 5. 用户实际使用后发生了什么？ | 首次任务耗时、上传了什么、练了几题、发现了什么薄弱点、最具体的一条抱怨 | 使用观察记录（第 5 节） |
| 6. 相似用户是谁？ | 先总结起点人物的三个特征（有资料、有截止日期、需要验证掌握），再列相似圈层 | 推理 + 第二位试用者更佳 |

## 5. 真实使用观察（提交前必做）

安排起点人物在**非开发机器**上完整用一次，团队旁观不代操作，记录以下各项（这份记录就是评分 20% 那部分的原材料）：

- 从注册到看到第一次判分用了多少分钟，卡在哪一步。
- TA 实际上传了什么资料（类型、页数）。
- TA 完成了几次作答，每次判分后 TA 说了什么。
- Agent 找到的薄弱点，TA 认不认。
- TA 抱怨里最具体的一条。
- 团队据此改了什么（哪次提交、什么改动）。
- 改完之后请 TA 再用一次，发生了什么变化。

最后三条构成官方要求的"反馈 → 修改 → 再验证"闭环案例，复赛材料里单独占一页。

## 6. 相似用户圈层

对外表达顺序：先把起点人物讲透，再扩展到圈层。

1. 用个人讲义、校内课件备考的大学生（校内考试没有公共题库）。
2. 备考资格证、职称、语言考试，手里有官方教材和自己笔记的人。
3. 需要在截止日期前系统复习、而不是零散问答的人。
4. 已经在用 AI 问问题，但发现"问过了"不等于"会做了"的人。

## 7. 叙事示例（格式参考，内容虚构，禁止直接提交）

以下仅示范填写后的语感，人物为虚构，任何字段不得原样出现在参赛材料中：

> RefineQ 最初为小禾设计。她是大三学生，10 月底考《数据库系统》期中，这门课占保研绩点权重很高。老师的课件有 27 份 PDF，她自己记了两本笔记，但从没完整翻过第二遍。她试过把课件发给 ChatGPT 提问，"当时觉得懂了，三天后做题还是不会"。她不缺解释，缺的是有人拿她的课件持续出题、判她的答案、告诉她还剩三周该先补哪块。
